# C6 — RV64 execution under QEMU

C6 extends the C5 machine-code boundary to executable RV64 validation.

## Contract

- FIR remains the semantic boundary; C6 does not add new language semantics.
- The same verified scalar FIR is lowered to RV64 CLIF and emitted as relocation-free machine code.
- C6 validates both deterministic emission and actual execution under `qemu-riscv64`.
- The execution harness writes the emitted function bytes to a temporary file and uses the RISC-V GNU assembler/linker to build a standards-compliant minimal Linux ELF wrapper. The wrapper places one scalar argument in `a0`, calls the emitted function, then exits with Linux syscall 93 using the function result.
- Calls between Forge functions, globals, relocations, dynamic linking, and a general Forge object/linker format remain outside C6.
- CI keeps one sequential job; QEMU validation runs inside the normal workspace-test stage.

## Required coverage

- Emitted RV64 machine code is non-empty and deterministic.
- The emitted function executes under QEMU for both sides of a conditional branch and the equality boundary.
- Existing AArch64 native execution remains covered by the same workspace test run.
- The C6 harness relies on `qemu-user` and `binutils-riscv64-linux-gnu`; ELF construction itself is deliberately not part of Forge C6.
