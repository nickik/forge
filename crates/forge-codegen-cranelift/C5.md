# Cranelift C5 — native machine-code execution

C5 extends the verified C4 FIR-to-CLIF pipeline through Cranelift machine-code emission and proves that the emitted AArch64 code executes correctly on a native AArch64 Linux runner.

## Supported boundary

- `PreparedModule` remains the input to machine-code emission.
- `CraneliftBackend::emit_machine_code` emits one selected prepared function.
- C5 accepts only relocation-free functions; calls/globals and linker semantics remain later milestones.
- `MachineCode` records target, FIR owner, and emitted bytes.
- Empty code buffers are errors.
- A prepared module may only be emitted by a backend for the same target.
- Requesting an owner absent from the prepared module is an error.

## Native execution proof

The C5 regression builds a scalar `u64 -> u64` FIR function using a wrapping integer add, lowers it through FIR -> CLIF -> AArch64 machine code, maps it W^X, flushes the AArch64 instruction cache, and calls it through the platform C ABI. It checks ordinary and wrapping inputs.

The repository keeps one CI job. From C5 onward that job runs on `ubuntu-24.04-arm`, so the ordinary workspace test step also performs the native AArch64 execution proof instead of adding a parallel architecture job.

## Deliberate boundaries

C5 does not define relocation/linking, external calls, globals, runtime initialization, or RV64 execution. RV64 execution is the C6 milestone.
