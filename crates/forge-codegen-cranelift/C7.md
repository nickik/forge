# C7 — Scalar memory and pointer lowering

C7 extends the scalar FIR backend with the first explicit Forge memory-layout boundary.

## Contract

- FIR remains the semantic boundary; C7 does not invent language-level aliasing, mutability, or pointer semantics.
- Forge owns scalar size and alignment through `ScalarLayout`. Cranelift value types are not the Forge layout specification.
- Addressable scalar locals use explicitly sized/aligned stack slots.
- Local, safe-reference, and non-volatile raw-pointer loads/stores lower to CLIF memory operations with exact FIR type checks.
- Stores through shared references are rejected. Mutable address-taking must refer to a mutable FIR local.
- Raw dereferences remain conservative and potentially trapping; volatile raw access is explicitly unsupported in C7.
- Pointer offsets preserve the exact pointer FIR type and scale integer offsets using the Forge layout of the pointee.
- Aggregate pointee layout, field/index places, closures, globals, calls, and relocations remain outside C7. Aggregate layout is deferred to C9 rather than inferred from CLIF.

## Scheduling

C7 value dependencies carried by dereference places, stores, and pointer offsets participate in the existing dependency scheduler. A valid dominance chain must not depend on incidental `FirFunction.blocks` vector order.

## Required coverage

- Scalar sizes and alignments are target-layout driven, including pointer-like values.
- Stack local load/store and safe-reference dereference lower on AArch64 and RV64.
- Non-volatile raw pointer load/store lowers on both targets; volatile raw access remains rejected.
- Pointer addition and subtraction use Forge pointee stride.
- Cross-block memory dependencies lower independently of block-vector order.
- Aggregate pointee arithmetic remains an explicit unsupported boundary until aggregate layout is defined.
